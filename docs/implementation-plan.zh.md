# 执行集成计划

[English](implementation-plan.md)

## 目标与边界

让执行内核更容易接入持久化部署控制器，保持账号、数据库、调度器、资源创建、脚本自动重试和分布式 fencing 在调用方。保留精确源码证据、新尝试工作区、有界输出、进程所有权和独立清理语义。

每阶段同步中英文文档，通过 `make lint` 和受影响 race 测试后独立提交。执行与适配器阶段还须通过 `make coverage`：核心至少 95%，每个适配器及辅助包至少 90%。提交只保留在本地。

## 证据

实施前 deployd 的 `go test -race -count=1 ./...` 已通过。对照控制器的配置、Sandbox 执行器和 Worker 定向测试也已通过。这些结果不证明真实 envd 兼容性。远程验收需要显式配置已有隔离目标，测试不创建或销毁基础资源。

阶段 1：兼容工具链 lint 与全包 race 覆盖率通过；核心 98.8%，envd 94.9%，local 95.6%，Git 96.6%，脱敏 100%。

阶段 2：兼容工具链 lint 与核心 race 测试通过；共享协议夹具与精确字节恢复示例通过。

阶段 3：兼容工具链 lint 与全包 race 覆盖率通过。真实测试已编译，未启用时跳过；当前 shell 未配置隔离 agent，远程验收仍未验证。

阶段 4：兼容工具链 lint 与全包 race 覆盖率通过；核心 98.8%，Git 97.6%。目标检出错误保留不确定进程清理身份，同时不暴露 provider 文本。

阶段 5：兼容工具链 lint、Go 1.27.1 全包 race 覆盖率和 Go 1.25.6 全包 race 测试通过。核心 98.7%，envd 95.8%，local 95.6%，Git 97.6%，脱敏 98.9%。检查点、日志与错误接口保持独立于资源编排。

## 接管合同

中断的尝试不通过相同操作标识再次调用 `Apply` 来恢复。控制器在启动前保存意图，通过 fencing 或串行化取得所有权，必要时核对并停止已保存的执行，再判断是否可创建新尝试。`Restore` 只恢复不可变计划。安装命令可能产生外部副作用；进程清理成功本身不代表可以安全重放脚本。
